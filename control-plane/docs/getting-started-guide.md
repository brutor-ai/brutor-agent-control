# Getting started: the Community Control Plane from source

From a checkout of this repository to a running Control Plane, a first sign-in and a first API
key, against a PostgreSQL and a Redis on your machine.

If you want to use Brutor Agent Control rather than work on the Control Plane, start the
Community package instead (seven containers, one command, nothing to build):
<https://docs.brutor.ai/installation/quickstart/>.

## What you need

- Python 3.13.
- Docker, for PostgreSQL and Redis.
- Nothing else for the steps below. The Community Edition needs no licence key, no Qdrant and
  no object store. To send traffic you also need the Core Gateway: it reads the configuration
  this service writes and carries all runtime traffic.

## 1. PostgreSQL and Redis

This repository has a Compose file for development infrastructure:

```bash
docker compose up -d
```

It starts PostgreSQL on port 5432 and Valkey (which speaks Redis's protocol) on 6379, on this
machine only. The database name, user and password are the ones that Compose file sets
(`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`).

## 2. Configuration

Configuration is read from the environment. A `.env` file in the working directory is loaded
at start, and `.env.example` lists every variable with its explanation (`python main.py
--print-env` prints the same as JSON).

```bash
cp .env.example .env
```

Then set the values a start depends on, in `.env` or in your shell:

```bash
export DATABASE_URL=postgresql://<user>:<password>@localhost:5432/<database>
export REDIS_URL=redis://localhost:6379/0
export JWT_SECRET=$(openssl rand -hex 32)
export ENCRYPTION_KEY=$(openssl rand -hex 32)
export BRUTOR_DEFAULT_TENANT_ADMIN_PASSWORD=<a password of your own>
```

Keep `JWT_SECRET` and `ENCRYPTION_KEY`: a later start with different values cannot read what
this one stored.

A start refuses an environment it cannot use, one line per name: a name the Control Plane no
longer reads (the line says what to set instead), a value that is not of its variable's type,
a required variable that is not set.

## 3. Install and start

The PostgreSQL driver (`psycopg2`) is built from source against the system's libpq, so
`pip install` needs `pg_config` on the `PATH` and a C compiler: on macOS
`brew install libpq` and `export PATH="$(brew --prefix libpq)/bin:$PATH"` (Xcode's command line
tools for the compiler); on Debian or Ubuntu `apt-get install libpq-dev gcc python3-dev`.

```bash
pip install -e ".[dev]"
python main.py            # http://localhost:5050
```

The first start creates the schema on an empty database, the tenant `default` and its
administrator (user name `admin` unless `BRUTOR_DEFAULT_TENANT_ADMIN_USERNAME` says otherwise). A
later start upgrades an existing database. Both happen under a lock, so several workers can
start at once.

Other ways to start:

```bash
python main.py --help                 # options: --listen-addr, --reload, --sql-echo, ...
python main.py init                   # only create the schema and seed, then exit
./start_with_gunicorn.sh community    # production: gunicorn app.app:create_app
```

Check it:

```bash
curl -s localhost:5050/health
```

The answer is a JSON document that begins `{"status":"healthy"`. It needs no credential.

## 4. Sign in

```bash
TOKEN=$(curl -s -X POST localhost:5050/v1/admin/users/tenant/login \
  -H 'Content-Type: application/json' \
  -d "{\"username\":\"admin\",\"password\":\"$BRUTOR_DEFAULT_TENANT_ADMIN_PASSWORD\",\"tenant_id\":\"default\"}" \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["access_token"])')
```

Five wrong passwords lock an account for 15 minutes. If the only administrator is locked,
`python main.py admin-unlock USERNAME` ends the lock.

## 5. A resource group and an API key

Every call to the Core Gateway is made with an API key bound to a resource group. Create both:

```bash
GID=$(curl -s -X POST localhost:5050/v1/admin/resource-groups -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"first-steps","display_name":"First steps","description":"getting started"}' \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print((d.get("group") or d)["id"])')

KEY=$(curl -s -X POST localhost:5050/v1/admin/resource-groups/$GID/api-keys -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"first-key","description":"getting started","access_mode":"shared"}' \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print(d.get("key_value") or d.get("full_key") or d.get("key"))')
```

The key is shown once.

## 6. Next: the Core Gateway and the Admin Console

- Start the Core Gateway with the same `DATABASE_URL`, `REDIS_URL`, `JWT_SECRET` and
  `ENCRYPTION_KEY`, and make a first call with the key: see the Core Gateway's
  getting-started guide.
- Start the Admin Console and sign in with the same administrator: see the Admin Console's
  getting-started guide. Models, MCP servers, guardrails and the rest are configured there.

## Tests

```bash
BRUTOR_TEST_EDITION=community pytest tests/
```

The suite needs no network and no running services (SQLite in memory). Some tests need
PostgreSQL. They run only when told where a throwaway server is, and each creates and drops
its own database there. Never point them at a database you keep:

```bash
BRUTOR_PG_TESTS=1 BRUTOR_PG_TEST_URL=postgresql://USER:PASSWORD@HOST:PORT/postgres pytest tests/
```

## Database changes

The Control Plane owns the schema. The Core Gateway never changes it. Models are in
`app/database/models/`, migrations in `alembic/versions/`:

```bash
alembic revision -m "describe the change"   # a new revision for every schema change
alembic upgrade head
alembic current
```

## What the Community Control Plane does not serve

Tenant management and the system administrator, the Knowledge
Base, the response and prompt caches, Policy-as-Code, traffic import, discovery, the MCP
Registry, model and MCP server deployment and batch jobs are Enterprise Edition features.
Their routes are not mounted in a Community Control Plane.

A Community start refuses a database that the Enterprise Edition has used and says so.
`python main.py edition-reset` deletes the Enterprise Edition's data from such a database; it
is a dry run unless given `--confirm-delete-enterprise-data`.
